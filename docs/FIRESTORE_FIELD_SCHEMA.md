# 24/7Nation Global Media — Firestore Field Schema

Status: Proposed implementation contract. This document defines the first version of the logical Firestore schema; it does not create collections or change deployed security rules.

## 1. Global conventions

- Use Firestore document IDs generated by Firestore unless a stable external ID is required.
- Store timestamps as Firestore Timestamp values. Trusted backend code must set `createdAt`, `updatedAt`, publication times and audit times using server timestamps.
- Store Firebase Authentication UID as `uid`; never store passwords, ID tokens, refresh tokens, service-account keys or API secrets.
- Use ISO 4217 currency codes if financial fields are introduced later. Do not add payment details to this first schema.
- Use explicit status enums rather than free-text status values.
- Keep public-facing fields separate from private/internal fields.
- Store uploaded media in Cloud Storage; Firestore stores metadata and the storage object path, not large binary files.
- All schemas below are version 1. Validate inputs on the trusted backend and apply Firestore Security Rules.

## 2. Organisation and departments

### `organisation/{organisationId}`

Required fields:
- `name: string` — 24/7Nation Global Media
- `tagline: string` — Rising A Voice For The North
- `brand: map` — approved colour tokens and logo asset references
- `publicContact: map` — approved public email, phone and address fields only
- `status: "active" | "inactive"`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Do not put private founder identity documents, bank details or personal contact records in the public organisation document.

### `departments/{departmentId}`

Required fields:
- `code: string` — stable values `music_records`, `global_media`, `family`, `mobile_app`, `website`, `community_portal`
- `name: string`
- `description: string`
- `pillarNumber: integer` — 1 through 6
- `status: "planned" | "active" | "paused"`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Pillar 2 contains Maidammanation Productions as an internal production arm. Do not create a seventh pillar for it. Nation Connect is a cross-platform service, not a pillar.

## 3. Identity and access

### `users/{uid}`

Document ID must equal the Firebase Authentication UID.

Required fields:
- `uid: string`
- `displayName: string`
- `email: string` — verified account email where available
- `photoAssetPath: string | null`
- `accountStatus: "invited" | "active" | "suspended" | "closed"`
- `createdAt: timestamp`
- `updatedAt: timestamp`
- `lastSignInAt: timestamp | null` — populated by trusted backend/auth event integration only

Never store passwords or authentication tokens here. Do not let a user assign their own privileged role by writing to this document.

### `roleAssignments/{assignmentId}`

Required fields:
- `uid: string`
- `role: "owner" | "super_admin" | "department_admin" | "editor" | "journalist" | "artist_manager" | "production_manager" | "community_manager" | "member"`
- `departmentCodes: string[]` — empty only when role scope is global by explicit policy
- `permissions: string[]` — optional explicit grants; backend must validate against the role policy
- `status: "pending" | "active" | "revoked"`
- `assignedByUid: string`
- `assignedAt: timestamp`
- `updatedAt: timestamp`
- `reason: string | null`

Only trusted owner-authorised backend operations may create, change or revoke role assignments. A super-admin must not be able to assign or replace the owner.

## 4. Editorial records

### `stories/{storyId}`

Required fields:
- `title: string`
- `slug: string`
- `summary: string`
- `body: string`
- `category: string`
- `tags: string[]`
- `status: "draft" | "in_review" | "approved" | "scheduled" | "published" | "archived"`
- `visibility: "public" | "members"`
- `authorUid: string`
- `reviewerUid: string | null`
- `approvedByUid: string | null`
- `publishedAt: timestamp | null`
- `sourceReferences: map[]` — title, publisher, URL and access date; no unsupported claims
- `mediaAssetIds: string[]`
- `correctionOfStoryId: string | null`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Drafts, private notes and stories in review must not be readable by the public. Only an authorised approver may move a story to approved or published.

## 5. Music and artist records

### `artists/{artistId}`

Required fields:
- `stageName: string`
- `slug: string`
- `publicBiography: string`
- `genreTags: string[]`
- `publicImageAssetId: string | null`
- `publicLinks: map`
- `managementStatus: "prospect" | "active" | "paused" | "archived"`
- `departmentCode: "music_records"`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Private contact details and contracts must be held in separately permissioned records, not in public artist profiles.

### `releases/{releaseId}`

Required fields:
- `artistIds: string[]`
- `title: string`
- `releaseType: "single" | "ep" | "album" | "video" | "other"`
- `releaseDate: timestamp | null`
- `status: "draft" | "scheduled" | "released" | "withdrawn"`
- `coverAssetId: string | null`
- `platformLinks: map`
- `credits: map[]`
- `rightsStatus: "unverified" | "pending" | "cleared" | "restricted"`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Do not mark rights as cleared without documented verification.

## 6. Productions and media library

### `productions/{productionId}`

Required fields:
- `title: string`
- `productionType: "interview" | "podcast" | "documentary" | "film" | "live_coverage" | "commercial" | "other"`
- `description: string`
- `status: "proposed" | "approved" | "in_production" | "post_production" | "completed" | "cancelled" | "archived"`
- `leadUid: string`
- `crewUids: string[]`
- `scheduledStartAt: timestamp | null`
- `scheduledEndAt: timestamp | null`
- `mediaAssetIds: string[]`
- `createdAt: timestamp`
- `updatedAt: timestamp`

This collection represents Maidammanation Productions within pillar 2.

### `mediaAssets/{assetId}`

Required fields:
- `storagePath: string`
- `fileName: string`
- `contentType: string`
- `sizeBytes: integer`
- `assetType: "image" | "video" | "audio" | "document" | "other"`
- `uploadedByUid: string`
- `departmentCode: string`
- `visibility: "private" | "internal" | "public"`
- `rightsStatus: "unknown" | "pending" | "cleared" | "restricted"`
- `creditLine: string | null`
- `consentReference: string | null`
- `usageExpiresAt: timestamp | null`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Validate file size, extension and actual content type on upload. Never make an asset public merely because its metadata says `visibility: "public"`; enforce access through Storage rules and an approved publishing workflow.

## 7. Community records

### `memberApplications/{applicationId}`

Required fields:
- `applicantUid: string`
- `displayName: string`
- `contactEmail: string`
- `applicationStatus: "submitted" | "under_review" | "approved" | "rejected" | "withdrawn"`
- `reviewedByUid: string | null`
- `reviewedAt: timestamp | null`
- `reviewReason: string | null`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Collect only information necessary for membership. Any sensitive or safeguarding-related details require a separately designed restricted workflow.

### `members/{memberId}`

Required fields:
- `uid: string`
- `displayName: string`
- `membershipStatus: "active" | "paused" | "suspended" | "ended"`
- `joinedAt: timestamp`
- `communicationPreferences: map`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Members may read and update only explicitly permitted fields of their own profile. They must never read other members' private data.

- `approvedByUid: string | null`

## 9. Audit history

### `auditEvents/{eventId}`

Required fields:
- `actorUid: string`
- `actorRoleAtTime: string`
- `action: string`
- `resourceType: string`
- `resourceId: string`
- `outcome: "success" | "denied" | "failure"`
- `occurredAt: timestamp` — server-generated
- `reason: string | null`
- `requestId: string | null`
- `metadata: map` — allowlisted, non-sensitive details only

Audit events must be written by trusted backend code and be append-only to application users. No normal user, department administrator or super-admin may update or delete audit events. Never record passwords, tokens, private keys or full sensitive payloads.

## 10. System settings

### `systemSettings/{settingId}`

Store only non-secret settings such as feature availability, public site preferences and safe operational limits. Secret keys, credentials and provider tokens belong in server-side secret storage, never Firestore documents accessible to clients.

## 11. Required indexes and query planning

Add composite indexes only after the first real queries are defined. Likely candidates include:
- stories by status + updatedAt
- stories by visibility + status + publishedAt
- productions by status + scheduledStartAt
- releases by status + releaseDate
- memberApplications by applicationStatus + createdAt
- auditEvents by actorUid + occurredAt and by resourceType + resourceId + occurredAt

Confirm actual Firestore index requirements from query errors and commit index definitions to source control.

## 12. Release gates before creating live records

- [ ] Owner approves the schema and data-retention policy.
- [ ] Trusted backend verifies Firebase ID tokens.
- [ ] Role assignments are written only by trusted owner-authorised operations.
- [ ] Firestore rules deny by default and are tested for each role.
- [ ] Audit events are server-written and immutable to clients.
- [ ] Cloud Storage rules validate access independently of metadata.
- [ ] Backup, export, correction and deletion procedures are documented.
- [ ] No real staff or member records are entered until these checks pass.

## 13. Current-state warning

This document is a schema blueprint only. It does not mean the listed collections, APIs, roles, audit history, upload workflows or management modules are currently implemented. Keep the current owner-only Firestore rules in place until a complete, tested replacement is ready.
